# Backend test strategy

Тесты backend защищают текущее поведение перед архитектурным рефакторингом.
Они не задают новую бизнес-логику: изменение перечисленных инвариантов должно
выполняться отдельной функциональной задачей.

## Критические инварианты

### Денежный журнал

1. Баланс счёта равен последнему `balance_after` его immutable-журнала.
2. Одна операция с одинаковым `idempotency_key` применяется ровно один раз.
3. Create exchange применяет обе отслеживаемые ноги и canonical source-link одной
   транзакцией; ошибка любого шага откатывает все записи без компенсационных проводок.
4. Cancel exchange возвращает обе ноги и является идемпотентным.
5. Edit exchange применяет только разницу сумм; смена валюты возвращает старые
   ноги и применяет новые.
6. Неотслеживаемая валюта не создаёт проводку.

### Заявки и CRM

1. Успешная Telegram-заявка сохраняет source-link с идентификаторами карточек.
2. Повторная регистрация одного `source_ref` не создаёт вторую CRM-сделку.
3. Статус CRM меняется только по разрешённому переходу.
4. Изменение статуса или source-данных создаёт дедуплицированную запись
   `tg_outbox`.
5. Outbox item может быть захвачен только одним worker и после ошибки либо
   возвращается на retry, либо становится terminal failed.
6. Ошибка Telegram после сохранения бизнес-операции не должна задваивать
   финансовый эффект при повторном вызове.
7. Telegram I/O выполняется только после commit финансовой операции и source-link.

### Cash requests

1. Create сохраняет schedule entry и ссылки на Telegram-карточку.
2. Edit синхронно обновляет клиентскую карточку, request-карточку и расписание.
3. Done/cancel деактивирует schedule entry, если она существует.
4. Issue меняет баланс только для существующего клиентского счёта.

## Команды проверки

Все unit-тесты без PostgreSQL:

```bash
.venv/bin/python -m pytest tests/unit -q
```

Полный backend suite с одноразовой локальной БД `crm_skyex_test`:

```bash
.venv/bin/python -m pytest
```

Использование заранее созданной тестовой БД:

```bash
TEST_DATABASE_URL=postgresql://user:password@127.0.0.1:5432/crm_skyex_test \
  .venv/bin/python -m pytest
```

Статический анализ:

```bash
.venv/bin/ruff check .
```

При изменении миграций полный suite необходимо запускать без
`TEST_DATABASE_URL`: fixture создаст пустую БД и применит Alembic до `head`.
